# Clotr engine 1.6.3 in detail

- A Secrets Manager password written without quotes, like `SecretString=…` in a log line or `SecretString: …` in
  YAML, is found, and Hide it covers it. A file, a variable or a reference there stays quiet, like
  `SecretString=file://secret.json` or `SecretString: !Ref DbPass`.
  In quotes, like `"SecretString":"…"` in JSON, it's found too. 1.6.2 misses both. Without quotes, a password with no
  digit, or one right after the colon with no space, is still missed, as on 1.6.2.
- A message with two login codes in it, like `482913 is my verification code: 551234`, has both codes found, and
  Hide it covers both. A backup code list now ends before the next code's name, so `902731, backup` isn't read as one.
  A second code inside an element, like `<note>…</note>`, or one with its own name after it, like
  `482913 is my login code, 551234 is the backup code`, is still missed, as on 1.6.2.
- A password inside an XML or HTML element, like `<note>password: …</note>`, is found without the closing tag, so
  Hide it covers only the password. A Secrets Manager ARN, like `arn:aws:secretsmanager:…:secret:prod/db-AbCdEf`,
  stays quiet. It used to read as a password.
  Since the ARN is quiet, a password in a query string before it, like `?SecretString=…&SecretId=arn:…`, gets no
  warning. 1.6.2 warns there only on the ARN, and its Hide it leaves the password showing too.
- A setting in backticks in a sentence, like `secret: true` or `token: auto`, stays quiet. It used to read as a
  password. A password in backticks is still found, now without the closing backtick.
  A one-word password with no digit goes quiet the same way, like `password: sunshine` in backticks. 1.6.2 found it
  only because the closing backtick counted as a mark, and without backticks neither version finds it.
- In inline code, a password that's a word and a number or two camelCase words under a password's dotted name, like
  `db.password.value=…` or `db.password.ref=…`, is found, as on 1.6.2. A quoted password there, or one that starts
  with a digit, is missed, though 1.6.2 finds it.
- A password or key one level under its name in YAML is found, like a CloudFormation parameter's `Default:`, a
  `value:` or `text:` under `password:`, or a list item under it. A value that's a variable, a reference or a
  placeholder stays quiet.
- A version range, a home path, an image digest, a YAML alias outside quotes or a link whose query holds only
  numbers, versions and words under a camelCase password setting stays quiet, like `adminPassword: ^2.3.1`,
  `passwordRef: ~/secrets/client2.json` or `vault://kv/db?version=3&env=prod`.
- Two or three backup or recovery labels in a comma list, then a number and a word, warn, like
  `Tags: backup codes, recovery codes, 2fa, tutorial`, where 1.6.2 is quiet.

## Read as on 1.6.2

These shapes were touched on the way to 1.6.3 and read the same as on 1.6.2.

- Under a camelCase password setting, a value with `#` in it, like `adminPassword: welcome#pass1` or
  `dbPassword: dogs-rule#password1`, is found.
- Under a camelCase password setting, the base64 of a password made of words and numbers, like the base64 of
  `welcome-1234` in a Kubernetes Secret's `data:` or in JSON, is found, and the base64 of a stored name, like
  `admin-user-2024`, is flagged.
- In a backup code list, a plain word before "code", "codes" or "key", like `backup codes: first code …, second
  code …`, stays inside the list, so every code is found and hidden. The list ends only at another backup or
  recovery label.
- Backup codes after a second label with a comma or semicolon right after it, like
  `backup codes {A} {B}, recovery codes, {C} {D}`, are all found and hidden.
- Two backup or recovery labels joined by "and", then a colon and a sentence with a number in it, like
  `my backup codes and recovery codes: 2024 is when I printed them` or
  `my backup codes and two-factor codes: not working since 2024`, stay quiet. So does a year or a small number and
  then a long or accented word after them, like `…: 2003, remaining` or `…: 2000 más`.
