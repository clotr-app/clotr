# Clotr engine 1.6.2 in detail

- A login code in quotes before its name, like `'482913' is my verification code`, is found, and Hide it covers
  the digits.
- The masked preview of a found value shows less. A password, PIN, backup code, seed phrase, two-step sign-in key,
  card security code, gift card code, private key or connection string shows only dots, and anything else longer
  than 8 characters shows at most a quarter of itself, like `AK…3N` for a 20-character key. `mask()` takes the
  finding's kind as a second argument for this, and ClotrHost's `check` passes it for the warning sentence in
  `words` as well as for each finding's `preview`.
- A password with a digit and a symbol like `!` or `#`, or a key, under a camelCase name in YAML or JSON, like
  `dbPassword: …` or `"apiKey": "…"`, is found, and so is one between `<dbPassword>` tags in XML. A name there stays
  quiet, like `passwordRef: pg-creds-v2` or `adminPasswordKey: adminPassword`.
- A password or key under a name that ends in Value, Ref, Reference or Arn is found, like
  `<SecretValue>…</SecretValue>`, `apiKeyRef: …` and `db.password.ref=…`. `apiKeyRef: stripe-live-key` and `db.password.ref=orders-db` stay quiet.
- National ID numbers in a table under a "Numéro national" or "r. č." column are found, as they are after the
  same words in a sentence.
- An image file name with a size mark, like `icon@2x.png`, stays quiet. It used to read as an email.
- `detect()` returns an empty list when it's given something that isn't text, like `undefined`, `null` or an array.
  It used to throw from inside the engine. A `String` object, like `new String("...")`, is still checked as the text
  `String()` gives for it, and if its own `toString` throws, as the text it holds.
- A made-up stand-in key counted down, like `fedcba98…`, or a short group said over and over, like `a1b2c3d4a1b2…`,
  stays quiet after a key's prefix. A random key after the same prefix is still found, and passwords, PINs and login
  tokens are read as before.
- A long paste of metric lines, like Prometheus output, is checked as fast as in 1.6.1 again.
- A second Hide it on a long paste with a saved word inside many longer words takes a moment again, not seconds.
- A file with long runs of blank lines takes a moment to check, where some JavaScript engines took tens of seconds.
- Fewer wrong warnings on everyday numbers, like lotto lines, order numbers near the word "card", git output and prices
  in other languages. Keys typed in pieces are found, and a few long pastes that took seconds now take a moment.
- API tokens in 19 more formats are found with no label in front, from services like Resend, Cerebras, CircleCI and
  AWS Bedrock, and so are the secret webhook links for Teams, Google Chat, IFTTT and Zapier.
- ID and tax numbers from 19 more European countries are caught, like a Swedish personnummer or a Danish CPR number,
  and so are a German pension number and a Polish NIP. Each is found after its label or under a table column named
  for it.
- `ClotrHost.redact()` hides a word saved in My details only where it stands as a word, as the extension does, and
  leaves a longer word that starts with it alone. A word glued to a digit, like Acme2, or inside Chinese, Japanese or
  Thai is still hidden, as in 1.6.1.
- A word saved in My details is found in more of the ways people type it, with Markdown, CSV or path marks between
  its words, inside code names, links and usernames, in HTML or text read with the wrong encoding, and in Chinese,
  Japanese or Korean with or without a space. A short word like Max is found in code only where it stands alone, so
  max_tokens stays quiet.
- `Clotr.mask()` throws a `TypeError` when it's given anything but a string. An array used to come back as dots, or
  with its first and last items whole.
- A token's storage-key constant made of common storage words, like `const TOKEN_KEY = 'app:authToken';`, stays
  quiet, since it holds the name a token is kept under. Random letters or a passphrase in its place are still found.
- A GitHub app token copied out of Markdown, with a backslash before each underscore, is found when one of its
  dotted parts starts with an underscore, as in `.\_`, or when an underscore comes right after a dash, as in `-\_`.
  So is a login token (JWT) or an Atlassian API token with `-\_` inside it.
- A key block whose body is only `…` or `...` stays quiet, as a placeholder. A real key block is still found.
- A `users.noreply.github.com` address stays quiet, since it hides the person's own address. Other addresses, with
  or without a plus tag, are found as before.
