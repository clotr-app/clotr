# Clotr engine 1.6.4 in detail

- A password in any link with a login is found as a connection string, whatever the scheme, like
  `smb://sam:hunter2!@nas.wibblecorp.io/share`, `ssh://deploy:wibble99@files.wibblecorp.io` or
  `ldap://sam:velvetotter@localhost/share`, and Hide it covers the whole link. 1.6.3 knew a short list of schemes.
  For the rest it read `password@host` as an email, so the warning said email, and it missed a password with a
  character an email can't hold, like the `!` in `hunter2!`, or a host with no dot, like `localhost`.
  A password with a space in it, like `sftp://sam:my pass@files.wibblecorp.io`, is covered whole too. 1.6.3 covered
  only the part after the space.
  A real login right after a stand-in one in the same run, like the second link in
  `SERVICES=postgres://user:password@localhost:5432/db,amqp://admin:fennel4274^@localhost/app`, is found. 1.6.3
  skipped it and left the password showing.
- A stand-in password in a link stays quiet. 1.6.3 read the same ones as stand-ins in its own link types, but as an
  email when the host had a dot, like `secret@db.wibblecorp.io`. The stand-ins are `password`, `pass`, `passwd`,
  `pwd`, `secret`, `changeme`, a run of `x` or `*`, and a doc's word like `example`, `your_password`,
  `your-password`, `your_password_here`, `yourpassword`, `placeholder`, `dummy` or `redacted`, in any case.
  A password that only looks made up is found, like `12345678`, `test_password`, `CHANGE_ME`, `example123` or
  `mydummy9`.
  A link password that starts with `<`, `{`, `$`, `[` or `%` reads as a blank for a template or code to fill, as on
  1.6.3, so `$(DB_PASSWORD)`, `$cfg->{password}`, `<<parameters.db_password>>` and
  `fmt.Sprintf("postgres://%s:%s@%s/db", …)` don't warn as a link. That goes for a real password written that way
  too, like `$uperS3cret!`. On those texts 1.6.4 gives 1.6.3's answer, an email on a dotted host included, apart
  from the other changes here. A real login after them in the same run is found, and a stand-in like `secret`
  stays quiet.
- A typed password that only sounds made up, like `password: example123!` or `password: aaaaaa1!`, is found. So is
  one under its own `.value` outside inline code, like `db.password.value=maple_2093`.
- A key after `sessionKey:` or `authKey:` is found as a service token, as a key after other names is. A crypto private
  key after `clave privada` is found, and so is a JWK whose quoted values hold a brace, like `"kid": "{main}"`.
- A key file's path under a key's name, like `apiKey: ./certs/server.pem`, stays quiet.
- Under a password's ref, arn or reference name, words that name a secret or where one is kept read as the
  reference, like `password_ref: prod database password` or `password_ref: orders vault entry`, and stay quiet.
  1.6.3 read them as a passphrase.
- A short sign-off after a question about a password, like the `Thanks!` in `I forgot what my password is. Thanks!`,
  stays quiet.
- A tag list or a dated sentence after a backup code label, like `Tags: backup codes, recovery codes, 2fa, tutorial`
  or `backup codes are not working since 2024`, isn't read as backup codes. 1.6.3 warned on both. A list with a code
  in it is still found, like `backup codes are not working since 2024 4829-1735 9921-0034`.
- A phone number spelled with `nought`, `naught` or `ninty`, or with extra spaces or a spaced hyphen between number
  words, like `fifty  three` or `fifty - three`, is read whole. A spelled-out SSN with a spaced hyphen inside a
  number, like `five three one, fifty - five, one two three four`, is now found as an SSN, where 1.6.3 called it a
  phone number.
  A few runs with `naught` or `nought` go quiet now, since the whole run isn't a valid number, like
  `nine six nine four five four two naught six eight seven`. 1.6.3 stopped at the word and warned on the first seven
  digits. With `zero` in its place both versions are quiet.
- Hide it covers a copy of a value behind a second layer of URL encoding, like an SSN written `%2535%2533%2531…`.
  1.6.3 covered the plain copy and one layer of encoding. What's found doesn't change.
- A counted-up password glued to a colon or a closing tag, like `mot de passe :12345678` or
  `my password is 12345678</password>`, now warns, with the colon or the tag inside what's covered. With a space
  before it, like `password: 12345678`, it stays quiet, as on 1.6.3.
- `Clotr.numberRuns()` renamed some fields. `afterEnd` is now `afterPeriod`, `atEdge` is now `edgeOk`, and the unit
  kinds `weak` and `letter` are now `soundAlike` and `lookAlike`. The npm package's `detect()` and `redact()` don't
  change.
- The engine's source is rewritten for reading, in 59 files grouped by what they find, where 1.6.3 had 3. The npm
  package is still one bundle, and nothing else in what it finds changes.

## Quiet now, found by 1.6.3

These went quiet as a side effect of the fixes above. They're on the known issues list.

- A recovery list of everyday words and one year, like `recovery codes: horse battery staple 2024`, is quiet. 1.6.3
  found it only because of the year, and the same words with no year are quiet on both.
- `backup codes are not working since 2024 '033745' is my verification code` is quiet. 1.6.3 warned on the wrong
  words, `not working since 2024`, and left the code showing, so both versions miss the code.

## Found now, quiet on 1.6.3

These came with reading every link type and with finding a real login after a stand-in one. They're on the known
issues list too.

- A link of a type 1.6.3 doesn't read, then an @ later in the same run with no space, reads as a login, like
  `{"ws":"wss://chat.wibblecorp.io:443","twitter":"@sam"}`. 1.6.3 does the same for its own link types, like
  `http://`.
- A SQL blank, a dunder blank, a doc word, Ruby's `#{pass}` or Swift's `\(pass)` as a link's password, like
  `smb://sam::password@nas/share`, `__PASSWORD__` or `mypassword`, warns in a link type 1.6.3 doesn't read. 1.6.3
  warns on the same passwords in its own link types, like `postgres://`.
- A stand-in login, then a link that isn't a login, then another stand-in login, in one run with no space, reads
  from the middle link to the last login's @ as a login, like the `http://` link and what follows it in
  `postgres://app:${PASS}@localhost/app;http://localhost:3000/api;postgres://app:${PASS}@localhost/app`. 1.6.3 is
  quiet there.

## Read as on 1.6.3

These shapes were touched on the way to 1.6.4 and read the same as on 1.6.3.

- The word password typed as the password, like `my password is password`, is found.
- A test login like `admin:test_pass_42` stays quiet.
- A counted-up password with a space before it, like `password: 12345678` or `my password is 12345678`, stays quiet.
- A link password with one layer of URL encoding, like `postgres://sam:hunter%25212@db.wibblecorp.io`, is found as a
  connection string.
- A database link right after a link that isn't a login, like `{"ws":"ws://localhost:8080/ws","db":"postgres://…"}`,
  is found.
- With no phone word near it, a number spoken from `nought`, like `it is nought seven four five nine one seven two
  nine nine eight`, is found from the word after `nought`.
- A passphrase of separate words under a password's ref name, like `db_password_ref: correct horse battery
  staple`, is found, and so is one under an `_arn` or `_reference` name. A joined name there, like
  `prod-db-password` or `arn:aws:…`, reads as on 1.6.3 too. The same words under a camelCase name, like
  `dbPasswordRef:`, are quiet on both.
