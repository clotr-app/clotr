# Clotr for Windows 1.6.4 in detail

1.6.4 carries engine 1.6.4. So it brings what engine 1.6.2, 1.6.3 and 1.6.4 changed, as well as the app's own changes
since 1.6.1. Each engine release has its own details in `apps/engine/docs/`, and this page names only what shows up in
the warning, in Clot this leak, in Check my files or in Look back.

## Known issues

- A phone number said with `nought` or `naught` as its first or last zero can get no warning, like
  `naught seven nine two two six six seven eight four` for 07 9226 6784. 1.6.1 warned on part of each one. That's
  135 of 2,000 made-up spoken numbers, all Australian or UK. 1.6.1's warning read part of the words as a phone
  number in 47 and as a US Social Security number in 88. With zero or oh in the nought's place, both versions miss
  all 135.
- A Secrets Manager password escaped inside the output of `aws secretsmanager get-secret-value`, beside its "ARN"
  line, gets no warning, since the ARN is quiet now. 1.6.1 warned only on the ARN and left the password showing. A
  password right before the secret's ARN in a query string is found, and Clot this leak covers it. It can stay quiet
  when the account in the ARN is a placeholder, like AWS's example `123456789012`.
- When a plain number comes right after a login code and "and", ", and" or "or", like
  `the login code is 482913 and 551234.`, it's read as a second code. The warning names two codes and Clot this leak
  hides both. 1.6.1 hides only the first.
- A path, a link or a timestamp under a camelCase setting like `authToken:` or `jwtSecret:` brings up a warning, like
  `authToken: /run/secrets/db_password`. 1.6.1 stays quiet there, but it warns on all three under `auth_token:`.
- Check my files still counts a UTF-16 text file clean in a few rare shapes, like big-endian with no byte order mark,
  UTF-32, or a zero byte inside the key. 1.6.1 counts all of them clean too.
- A typed message is read to 20,000 characters, and the rest isn't checked or mentioned. A copy over 2,000,000
  characters gets no warning at all. 1.6.1 does both of these too.

## The app

- The main window's web view keeps the Windows sign-in lookup off. WebView2 157 turned it back on through
  `msForceOneAuthWAM`, so 1.6.1 could reach Microsoft's sign-in servers when it opened. Clotr never signs in to
  anything.
- Light is a look again in Settings, beside Plum and Ember, with Clotr for Android's Light colors. A look picked
  before is kept after a restart.
- The warning says when the time limit cut a copy or a typed message short. Before, it said nothing if nothing turned
  up before the cut.
- Check my files reads text saved as UTF-16, with or without a byte order mark, and a UTF-8 line added to one. With
  the developer switch on, it reads sign-in files with no extension too, like `.pgpass`, `.git-credentials`,
  `.pypirc` and `id_dsa`. 1.6.1 counted 20 of those names clean with a key inside.
- A file the time limit cut short shows as not read, and Save a copy keeps no hidden copy of it. 1.6.1 counted it
  read and clean.
- After the update, the first scan reads everything in reach again, even if a Full scan ran before. 1.6.1's Full scan
  record could hold files counted clean without being read, so a changes-only scan would have skipped them. The Scan
  screen says why. The next Full scan writes a new record.
- When a scan finds nothing but couldn't read some files, the finish, Results and Save a summary say how many and why.
  An empty folder says there were no files to check. A stopped scan's summary says it was stopped and how many files
  it read.
- A file that takes more than 20 seconds to read, or a reader that stops working, shows as not read and the scan goes
  on. Three in a row end the scan. 1.6.1 could wait forever on one file.
- A zip's list is read once for each reader instead of once for each entry. With 8 readers 1.6.1 took 8.4 s for 2,000
  small entries and 45.4 s for 5,000, so a big enough zip could keep the weekly check from ever finishing.
- Results and Check my files name a file by its key when it holds an email and a key, like a GitLab or Hugging Face
  token, for every key kind the engine has. Look back shows xAI keys and backup codes in red.
- The app's Rust source moved out of a few long files into folders by role, like `check_my_files/`, `warning_card/`
  and `tray/`, and its pages into folders like `ui/card/` and `ui/results/`. The build, the settings
  file and everything the app does stay the same.

## What the engine brings

These are the engine changes a Windows user meets. Each was tried on a made-up example in the 1.6.1 and 1.6.4
bundles.

- A password in a link with a login is found as a connection string, whatever the link's type, like
  `smb://sam:hunter2!@nas.wibblecorp.io/share`, which 1.6.1 missed. Clot this leak covers the whole link.
- A stand-in password in a link to a real host, like `mysql://admin:password@db.wibblecorp.io/app`, stays quiet.
  1.6.1 read it as an email.
- Tokens in 19 more formats are found with no label in front, like a Resend key, and so are the secret webhook links
  for Teams, Google Chat, IFTTT and Zapier.
- A password under a camelCase name in a config file is found, like `dbPassword: …`, and so is one under
  `SecretString:`, a key after `sessionKey:` or `authKey:`, and a typed password that only sounds made up, like
  `password: example123!`.
- ID and tax numbers from 19 more European countries are found after their label or under a column named for them,
  like a Swedish personnummer.
- A second login code in one message is found too, like `482913 is my verification code: 551234`. See the known issue
  above.
- Most phone numbers spelled with `nought`, `naught` or `ninty` are found whole, like
  `call me at four one five, five five five, ninty one twenty three`. In 2,000 made-up spoken numbers 1.6.4 warns on
  661 that 1.6.1 misses. See the first known issue for the ones it doesn't.
- More everyday numbers stay quiet, like order, invoice and tracking numbers, dates with times and prices in other
  languages. So do image names like `icon@2x.png`, a key file's path like `apiKey: ./certs/server.pem`, a setting in
  backticks like `secret: true`, and a `users.noreply.github.com` address.
- The preview in the warning shows only dots for a password, PIN, backup code, seed phrase, private key or connection
  string, and at most a quarter of anything else longer than 8 characters, like `AK…3N` for a 20-character key.

## Checked against 1.6.1

The engine corpus went through the 1.6.1 and 1.6.4 Windows bundles: 31,670 texts, the 21 corpus files, 2,000
generated texts and every label probe. Nothing threw. 43 findings in 38 everyday messages went quiet, 41 phone
numbers and 2 card numbers that were order numbers, dates and prices. No finding was added, renamed or resized, and
nothing 1.6.1's Clot this leak covers is left showing by 1.6.4's, apart from those 43 everyday numbers.
