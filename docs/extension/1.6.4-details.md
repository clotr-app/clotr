# Clotr 1.6.4 in detail

Everything here is next to 1.6.1, the last public extension. The engine inside it went from 1.6.1 to 1.6.4, and its own notes are in `apps/engine/CHANGELOG.md`.

- A password in any link with a login is found as a connection string, whatever the scheme, like "smb://sam:hunter2!@nas.wibblecorp.io/share", "ssh://deploy:wibble99@files.wibblecorp.io" or "ldap://sam:velvetotter@localhost/share", and Hide it covers the whole link. 1.6.1 read many of these as an email and missed the rest. A password with a space in it is covered whole, and so is a real login right after a stand-in one in the same run.
- A stand-in password in a link stays quiet, like "postgres://admin:password@db.wibblecorp.io/app". The stand-ins are password, pass, passwd, pwd, secret, changeme, a run of x or *, and a doc's word like example, your_password, placeholder, dummy or redacted. 1.6.1 warned on many of them as an email. A link password that starts with <, {, $, [ or % reads as a blank for code to fill, as on 1.6.1.
- A password with a digit and a symbol, or a key, under a camelCase name in YAML, JSON or XML is found, like "dbPassword: Wibble#42door" or "<dbPassword>Fennel!8842</dbPassword>", and so is one under a name that ends in Value, Ref or Arn. A name there stays quiet, like "passwordRef: pg-creds-v2", and so does a version range or a home path.
- A password one level under its name in YAML is found, like a CloudFormation parameter's "Default:" or a "value:" under "password:".
- A Secrets Manager password is found in a log line, in YAML and in JSON, like "SecretString=Wibble2093pass". A reference there stays quiet, like "SecretString: !Ref DbPass", and so does the secret's ARN, which 1.6.1 read as a password.
- A login code in quotes before its name, like "'482913' is my verification code", is found. A message with two login codes, like "482913 is my verification code: 551234", has both found and hidden, where 1.6.1 hid only the first.
- A typed password that only sounds made up, like "password: example123!", is found, and so is one under its own ".value", like "db.password.value=maple_2093". A counted-up password glued to a colon or a closing tag, like "mot de passe :12345678", warns too.
- A key after "sessionKey:" or "authKey:" is found, and so are a crypto private key after "clave privada" and a JWK with a brace in a quoted value.
- API tokens in 19 more formats are found with no label in front, from services like Cerebras, CircleCI and AWS Bedrock, and so are the secret webhook links for Teams, Google Chat, IFTTT and Zapier.
- ID and tax numbers from 19 more European countries are found after their label or under a table column named for them, like a Swedish personnummer, a Danish CPR number, a German pension number or a Polish NIP.
- A word saved in My details is found in more of the ways people type it: with Markdown, CSV or path marks between its words, inside code names, links and usernames, in text read with the wrong encoding, and in Chinese, Japanese or Korean with or without a space. A short word like Max is found in code only where it stands alone, so max_tokens stays quiet.
- Most phone numbers spelled with nought, naught or ninty are found whole, and so is one with a spaced hyphen between number words, like "fifty - three". In 2,000 made-up spoken numbers 1.6.4 warns on 661 that 1.6.1 misses.
- Hide it covers a password inside an XML or HTML element without its closing tag, a password in backticks without the closing backtick, and a copy of a value behind a second layer of URL encoding.
- The warning's preview shows less of what it found. A password, PIN, backup code, recovery phrase, two-step key, card security code, gift card code, private key or connection string shows only dots, and anything else longer than 8 characters shows at most a quarter of itself, like "AK…3N" for a 20-character key.
- Fewer false alarms on everyday numbers in other languages, like dates with times, order, invoice and booking numbers, prices and lotto lines. The same goes for image names like "icon@2x.png", users.noreply.github.com addresses, made-up stand-in keys counted down like "fedcba98…", and a key block that's only "...".
- Fewer false alarms in developer text too: a setting in backticks like "secret: true", a key file's path like "apiKey: ./certs/server.pem", a note under a password's ref name like "password_ref: prod database password", the "Thanks!" after a question about a password, and a tag list or a dated sentence after a backup code label.
- A password made of a test word, "pass" and a number, like "password: test_pass_42" or "demo_pass_42", stays quiet, where 1.6.1 warned. One with a mark or another word in it, like "Test_Pass_42!" or "test_lantern_42", still warns.
- When an attached file is too long to check all the way through and nothing turned up in the part Clotr checked, Clotr says part of it wasn't checked, as it already does for a long message. Is this a scam? says so too when it couldn't look all the way through for your own details.
- On a phone, the welcome page keeps telling you how to find Clotr in the browser's menu, even when the browser says Clotr is pinned.
- The source is now readable files grouped by what they do. The engine is 59 files grouped by what they find, where 1.6.1 had 3, and the extension's own scripts were rewritten the same way. Nothing about how Clotr works for you changes.

## Known issues

- A phone number said with nought or naught as its first or last zero can get no warning, like "naught seven nine two two six six seven eight four" for 07 9226 6784, or "oh eight four four oh one one two six nought". It's 135 of the 2,000 made-up spoken numbers, all Australian or UK. 1.6.1 warned on part of each one, reading the words as a phone number in 47 and as a US Social Security number in 88. With zero or oh in its place both versions miss it.
- A plain number right after a login code and "and" or "or", like "the login code is 482913 and 551234.", is read as a second code, so Hide it covers it too.
- Under a camelCase setting like "authToken:" or "jwtSecret:", a file path or a time can warn as a password, like "authToken: /run/secrets/db_password". 1.6.1 warns on the same value under "auth_token:".
- In inline code, a name under a password's dotted ".value" setting, like "db.password.value: orders-db", warns as a password. 1.6.1 is quiet there.
- A code in a sign-in or verify link, like "?code=…", and a reset token in a link in angle brackets aren't hidden yet, as in 1.6.1.
- A Secrets Manager password in a query string right before the secret's ARN, like "?SecretString=…&SecretId=arn:…", gets no warning when the ARN holds a placeholder account like AWS's example 123456789012. With an ordinary account number 1.6.4 finds the password, and Hide it covers it along with the ARN. The escaped password in `aws secretsmanager get-secret-value` output beside its "ARN" line gets no warning, since the ARN is quiet now. 1.6.1 warned only on the ARN and left the password showing.
- Pages load the engine's 59 files a little later than 1.6.1's 3, about 12 to 18 ms on a chat page and 22 ms for the popup.

## Quiet now, found by 1.6.1

These went quiet as a side effect of the fixes above.

- A recovery list of everyday words and one year, like "recovery codes: horse battery staple 2024", is quiet. 1.6.1 found it only because of the year, and the same words with no year are quiet on both.
- 12 spelled-out number runs with nought or naught go quiet, since the whole run isn't a valid phone number or SSN, like "nine six nine four five four two naught six eight seven". 1.6.1 stopped at the word and warned on the digits before it. With zero in its place both versions are quiet.
- In two spelled-out runs with naught or nought and zero, Hide it leaves one or two number words showing at the edge of the phone number it covers.
